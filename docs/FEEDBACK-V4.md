# moov. 업데이트·채팅·활동 기록 피드백 (2026-11-23)

> 이 문서는 해당 기능 도입 당시의 기록입니다. 현재 종료 기준과 자동 갱신 정책은 [버전 9 변경 내용](V9-UPDATE.md)을 우선 확인하세요.

대상: 기존 온라인 개발 사이트. 공개 시연 사이트, GitHub, Firebase 계정/로그인 설정 변경 없음.

## 변경 사항
- 마이페이지 → 홈 화면에 추가 → 앱 업데이트: 서비스 워커 업데이트 확인, 활성화 후 새로 열기. Firebase 저장소 및 사용자 데이터를 지우지 않음.
- PWA 문서 요청은 온라인 최신 HTML 우선, 실패하면 캐시로 열기. API는 계속 캐시하지 않음. 업데이트 중 작성 화면을 강제로 새로고침하지 않음.
- 채팅 입력창 3줄/100px, 하단 메뉴 위에 고정되는 화면 구성. 모바일 키보드 표시 시 화면 높이 조정 및 하단 메뉴 일시 숨김.
- 수동 채팅 종료 UI 및 서버 명령 제거. 명칭은 경기 채팅으로 변경.
- 사용자가 확정한 기준: 실제 시작 기록(startedAt) + 2시간. 시작 예정 시각 기준 아님. 자동 시작된 경기도 저장된 실제 상태 전환 시각을 사용. 2시간 전에 경기를 조기 종료하더라도 채팅은 해당 마감까지 유지.
- 실제 시작 기록이 없는 이전 경기만 시작 예정 시각 + 2시간을 대체 기준으로 사용. 이전 정책에 따라 이미 삭제된 채팅은 복원하지 않음.
- 취소 또는 허위 경기 판정 시 D1 트리거가 채팅 원문/공지를 즉시 삭제. 신고 메타데이터는 유지.
- 예약 작업 없이 시간 만료는 모든 채팅 조회·전송에서 서버 시각으로 차단하고 해당 방 원문/공지를 삭제. 열려 있는 화면도 마감 시각에 재조회. 아무 접속도 없는 방의 정확한 마감 시각 물리적 삭제는 보장하지 않음. 외부 스케줄러/유료 서비스 추가 없음.
- 알림 내역 전체삭제: 본인 알림 내용만 지우고 목록에서 제외. 경기/매너 기록은 유지. 재발송으로 삭제한 알림이 되살아나지 않도록 최소 전달 ID와 삭제 시각은 남김.
- 내 활동: 내가 신청/내가 모집. 모집자는 내가 모집에만 노출. 취소·거절 제외, 예정/진행 및 종료 후 24시간 이내 활동. 목록은 10건씩 조회.
- 마이페이지 → 운동한 기록 보기: 신청한 경기/모집한 경기 구분. 지난 경기와 취소·철회·거절 기록 보존, 10건부터 지난 기록 더보기. 상세에서 되돌아가면 기록 화면의 해당 탭으로 이동.
- 20초마다 전체 서버 데이터를 가져오던 주기 제거. 초기 진입, 화면 이동/앱 복귀(30초 간격 제한), 사용자 조작 및 수동 새로고침으로 갱신. 채팅의 화면을 보고 있을 때만 10초 간격 새 메시지 확인은 유지.
- 활동 화면은 상위 데이터 참조 변경에 따라 초기화하지 않음. 복귀/수동 새로고침 시 이미 펼친 페이지 수를 유지하며 새 결과가 준비될 때 교체.

## 검증
- TypeScript 및 배포 빌드 통과.
- 로컬 Worker/D1 테스트 64개 통과: 기존 모집/신청/승인/정원/팀/매너/신고 회귀, 실제 시작+2시간 경계, 조기 종료 유지, 취소·전송 경합 삭제, 삭제 이후 전송 방지, 알림 소유자 격리·중복 처리, 활동 기간·중복 제거·기록 보존, PWA 최신 HTML/오프라인 대체/API 캐시 제외.
- 390×844 브라우저: 채팅 입력 높이 100px, 입력창 하단 748px/하단 메뉴 시작 777px로 겹침 없음. 기록 10→20건, 상위 상태 갱신 후 20건 및 요청 수 유지. 업데이트 버튼 위치 확인.
- Firebase 실제 메일/자동 로그인은 사용자 요청에 따라 별도 재검증하지 않음. iOS/Android 홈 화면 설치 앱 및 소프트 키보드는 실기기 검증 필요.
- 과거 실제 시작 기록이 없는 경기의 종료 시각은 기존 종료 시각 또는 예정 종료를 이용해 목록 분류하며 출석을 자동 인정하지 않음.
