# 경기 전 텍스트 채팅

> 이 문서는 해당 기능 도입 당시의 기록입니다. 현재 종료 기준과 자동 갱신 정책은 [버전 9 변경 내용](V9-UPDATE.md)을 우선 확인하세요.

2026-11-22. 기존 온라인 개발 Site에 추가한 기능이다. 별도 Firebase DB나 외부 스케줄러를 만들지 않는다.

## 사용 흐름

- 경기 상세 / 신청자 관리 → 경기 전 채팅. 모집자와 승인·참가 동의가 완료된 회원만 이용한다.
- 텍스트 최대 500자, 방당 최대 500개. 최근 50개만 읽고 마지막 메시지 이후의 새 글을 가져온다.
- 열려 있고 화면에 표시되는 채팅에서만 10초 간격으로 확인한다. 다른 화면·숨겨진 탭·오프라인에서는 중단한다. 서버 푸시나 WebSocket 채팅은 아니다.
- 모집자 공지 작성·수정·삭제. 일반 참가자는 읽기만 가능하다.
- 모집자가 경기 시작/취소를 처리하거나 채팅 종료 버튼을 누르면 대화 원문과 공지를 DB에서 삭제한다. 채팅만 종료해도 경기 자체는 유지된다. 종료한 방은 재개하지 않는다.
- 별도의 1:1 쪽지는 이번 버전에 포함하지 않는다.

## 삭제의 범위와 시점

`chat_rooms`에는 경기 ID, 생성/종료 시각·사유만 남고 `announcement`는 NULL이 된다. `chat_messages` 원문은 삭제하며 별도 대화 보관 테이블, 신고 사본, 메시지 로그를 만들지 않는다. 브라우저 localStorage/IndexedDB/서비스 워커 캐시에도 채팅을 보관하지 않는다. 참가자가 이미 복사하거나 캡처한 내용과 호스팅 제공자의 백업 보존까지 원격 삭제하는 기능은 아니다. 따라서 물리적 저장장치·제공자 복구 이력에서 즉시 제거된다고 보장하지 않는다.

종료/시작/취소 업데이트와 메시지 삭제는 D1 트리거로 같은 트랜잭션에 들어간다. 동시 전송도 SQL에서 현재 참가·종료 상태를 재검증하므로 종료 뒤 남지 않는다. 클라이언트 화면에서는 다음 응답 때(보통 최대 10초 + 네트워크 지연) 제거한다. 숨김·오프라인·권한 오류에서도 보유한 메시지를 비운다.

정확한 시각에 무인 실행하는 스케줄러는 없다. 실제 경기 시작/취소 명령에 따른 삭제는 즉시 수행한다. 시작 처리가 없는 v2 경기는 예정 종료시각이 지난 뒤 해당 방에 첫 요청이 오면 삭제한다. v1 경기는 예정 시작시각 이후 첫 요청에서 삭제한다. 요청이 없는 방을 그 시각에 물리적으로 삭제한다고 보고하면 안 된다. 기존 경기 lifecycle 호출이 시작/취소/종료 상태를 변경할 때도 트리거가 작동한다.

## 신고

- 사유: 욕설 및 비하 / 위협적인 발언 / 성희롱·불쾌한 발언 / 스팸·광고 / 개인정보 노출.
- 같은 회원은 한 방을 한 번 신고한다. 하루 일반 신고 합계 최대 5건. 허위 신고만으로 자동 매너온도 차감·이용 제한하지 않는다.
- 기존 `generalReports`에 `targetType='chat'`으로 저장한다. 경기 ID, 신고자 ID, 사유, 시각과 검토 상태만 보관하고 대화 내용을 복사하지 않는다.
- 운영자: 내 활동 → 운영자 전용 신고 관리 → 채팅방 확인. 검토 대기 신고가 있는 방만 추가 열람 권한을 부여한다. 운영자라도 일반 참가 자격 없이 메시지를 보내거나 방을 닫을 수 없다.
- 종료 후 운영자도 원문을 조회할 수 없다. 신고 사유만으로 사실을 확정하지 않는다. 검토 결과에 대화 원문을 복사하지 않도록 안내한다. 신고자 신원은 일반 참가자에게 공개하지 않는다.

## 서버와 DB

- Firebase 검증을 거치는 `GET/POST /api/chat`. 기존 인증 환경값·계정은 유지한다.
- `server/chat.mjs`: 읽기, 전송, 공지, 종료, 신고. 모든 쓰기의 SQL 내부에서 최신 권한을 다시 검증한다.
- `src/domain/chat.ts`: 공유 제한값·타입. `src/screens/Chat.tsx`: 화면과 활성 화면 갱신.
- 새 마이그레이션 `0005_bored_young_avengers`: chat_rooms, chat_messages, 인덱스, 종료 연동 트리거. 기존 20개 테이블/행을 이동·삭제하지 않는다. 적용된 0000~0004는 변경하지 않는다.
- 메시지 nonce 유일성으로 재전송 중복 방지, 3초 간격/분당 12건/방 500건을 SQL에서 원자적으로 검사한다.
- 무료 운영을 보장하는 기능은 아니다. 저장량은 제한하지만 화면이 열려 있으면 조회 및 Firebase 토큰 검증 요청이 발생한다. 이용량이 커지면 실제 사용량을 확인해 갱신 간격 또는 전송 방식을 조정한다.

## 검증 범위

- 프로덕션 빌드 통과. 로컬 Miniflare D1의 기존 및 채팅 테스트 총 54개 통과.
- 권한/참가 동의/참가 취소/권한 위임, 중복 전송, 동시 전송 한도, 종료와 전송 경합, 시작·취소 트리거 삭제, 신고 원문 미보관, 운영자 권한 검증.
- v5 백업의 20개 테이블 59건을 로컬에 복원하고 새 마이그레이션 후 모든 셀 값을 대조해 일치 확인.
- 로컬 브라우저에서 두 테스트 계정의 텍스트 전송·공지·신고 접수·채팅 종료·운영자 신고 목록 확인. 모바일 너비에서 메시지 16px, 가로 넘침 없음 확인.
- 실제 Firebase 계정 두 개와 서로 다른 스마트폰을 이용한 온라인 채팅은 별도 실기기 검증이 필요하다. 이 테스트를 완료했다고 보고하지 않는다.
- 백업 및 테스트 출력은 프로젝트 외부 `work/moov-v3-chat-backup`에 둔다. 개인정보가 포함된 D1 백업은 소스 저장소에 커밋하지 않는다.
